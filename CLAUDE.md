# Applawyer — CLAUDE.md

## Проект
Маркетплейс юридических услуг для Казахстана. Клиенты находят юристов, юристы получают заявки.
Стек: Flutter + Supabase (PostgreSQL, Auth, Storage, RLS).

## Роли пользователей
- `client` — ищет юриста, создаёт заявки
- `lawyer` — принимает заявки, управляет профилем
- Роль определяется полем `role` в таблице `profiles`
- AuthRouter направляет по роли после входа

## Локализация
- Поддерживаются 3 языка: казахский (kk), русский (ru), английский (en)
- Используется пакет `easy_localization`
- Все строки интерфейса — только через локализационные ключи, не хардкодить текст
- Файлы переводов: `assets/translations/`

## Supabase / Безопасность
- **Никогда** не хардкодить URL и anon key в коде — только через `.env` или конфиг
- Все таблицы защищены RLS — всегда проверяй, что политики покрывают операцию
- Авторизация на стороне сервера через RLS, не только на клиенте
- При создании новых таблиц — сразу добавлять RLS политики
- Не использовать `service_role` key на клиенте

## Flutter — правила кода
- Один виджет = один файл
- Называть файлы в `snake_case`, классы в `PascalCase`
- Не использовать `BuildContext` после `async` без проверки `mounted`
- Извлекать повторяющиеся виджеты в отдельные компоненты
- Не дублировать логику — выносить в сервисы/хелперы

## Структура проекта
```
lib/
  main.dart
  app/
    router/         # AuthRouter и навигация
    theme/          # цвета, стили
  features/
    auth/           # вход, регистрация, сброс пароля
    client/         # экраны клиента
    lawyer/         # экраны юриста
    shared/         # общие виджеты
  services/         # Supabase вызовы, бизнес-логика
  models/           # data классы
assets/
  translations/     # kk.json, ru.json, en.json
```

## Категории юридических услуг
Гражданское право, Семейное право, Уголовное право, Трудовое право, Корпоративное право, Налоговое право, Недвижимость, Миграционное право, Интеллектуальная собственность, Административное право

## Что нельзя трогать без явного запроса
- Файлы конфигурации Supabase (`.env`, `supabase/config.toml`)
- RLS политики в миграциях — только предлагать изменения, не применять
- `pubspec.yaml` — не добавлять зависимости без подтверждения

## Стиль работы
- Перед изменением файла — сначала прочитай его целиком
- При баге — сначала найди причину, потом исправляй
- Не переписывай рабочий код без необходимости
- Если задача неоднозначна — уточни перед выполнением
- Комментарии в коде на русском языке

## Частые задачи
- Добавить экран → создать в `features/`, добавить роут в router
- Добавить строку перевода → добавить ключ во все 3 файла (kk/ru/en)
- Добавить таблицу Supabase → написать миграцию + RLS политики
- Исправить баг авторизации → проверить AuthRouter и RLS одновременно
